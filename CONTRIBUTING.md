# Участие в проекте

Спасибо, что хотите помочь. Проект небольшой, поэтому правила простые.

## Перед началом

- Прочитайте [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
- Для крупных изменений сначала откройте issue: обсудим подход, чтобы не переделывать PR.
- Уязвимости не обсуждаются в публичных issue — см. [SECURITY.md](SECURITY.md).

## Настройка

```bash
git clone https://github.com/<ваш-аккаунт>/praxis.git
cd praxis
flutter pub get
cp env.example.json env.json   # Windows: copy env.example.json env.json
flutter run --dart-define-from-file=env.json
```

Для запуска нужен свой проект Supabase с применёнными миграциями: [docs/database.md](docs/database.md).

## Ветки и коммиты

- Ветка от `main`: `feat/short-name`, `fix/short-name`, `docs/short-name`.
- Коммиты — [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `docs:`, `test:`, `refactor:`, `chore:`.
- Один PR — одна тема. Не смешивайте переименование файлов и правку логики.

## Требования к коду

- `dart format .` — форматирование обязательно.
- `flutter analyze` — без ошибок и предупреждений.
- `flutter test` — все тесты зелёные.
- Новые зависимости — только с обоснованием в PR: проект намеренно обходится без лишних пакетов.
- Тексты интерфейса — по правилам из [docs/engineering-notes.md](docs/engineering-notes.md); их проверяет `test/ui_text_test.dart`.
- Экономику считает сервер. Прямые записи профиля с клиента не добавляются — это проверяет `test/client_invariants_test.dart`.

## Миграции базы

- Новая миграция — новый файл `migrations/NNN_short_description.sql` со следующим номером.
- Уже применённые миграции не редактируются: изменения оформляются новым файлом.
- Если меняете баланс, синхронизируйте `lib/constants/game_config.dart` и SQL: расхождение поймает `test/server_config_sync_test.dart`.
- Опасные разовые операции не кладите в `migrations/` — для них есть `scripts/`.

## Секреты

В репозиторий не попадают:

- `env.json` с реальными ключами Supabase;
- `android/key.properties` и `*.jks` — ключ подписи;
- `docs/.telegraph_state.json` — токен статьи;
- `service_role` ключ Supabase — он не должен покидать сервер ни при каких условиях.

Перед коммитом проверьте `git status` и `git diff --cached`. Если секрет уже попал в коммит, недостаточно удалить файл: ключ нужно отозвать и перевыпустить.

## Лицензия вкладов

Проект распространяется на некоммерческих условиях — см. [LICENSE](LICENSE). Отправляя pull request, вы подтверждаете, что:

- у вас есть право на этот вклад и он не нарушает права третьих лиц;
- вы разрешаете правообладателю использовать вклад в проекте, изменять его и распространять в составе проекта без отдельного вознаграждения;
- для существенных вкладов правообладатель может попросить отдельное письменное подтверждение.

Если вы не согласны с этими условиями, не отправляйте PR — вместо этого можно открыть issue с описанием проблемы.

## Pull request

В описании укажите:

- что меняется и зачем;
- как проверяли (`flutter analyze`, `flutter test`, ручной сценарий);
- для UI — скриншот до/после;
- для базы — номер миграции и порядок применения.

CI прогоняет анализ и тесты на каждый PR. Красный CI — повод разобраться, а не игнорировать.
