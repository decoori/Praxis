# Инженерные заметки

Документ собирает то, что не поместилось в README: как устроены тесты-сторожа, что сделано для производительности, правила текстов интерфейса и известные ограничения.

## Тесты

```bash
flutter analyze
flutter test
```

Тесты не обращаются к сети и не требуют Supabase: проверяются конфиги (бонусы построек, цены, целостность описаний), лимиты магазина, диалог промокода и офлайн-логика контроллера.

| Файл | Что держит |
|---|---|
| `test/server_config_sync_test.dart` | сверяет `lib/constants/game_config.dart` с балансом в SQL: постройки (`camp_building_effects`, миграция 006), эпохи (`era_config`, 012) и цены слотов (`goal_slot_prices`, 015). Баланс дублируется в Dart и в SQL намеренно — сервер обязан проверять цены сам, а не доверять клиенту. Если тест упал, два источника правды разошлись: правьте оба места |
| `test/client_invariants_test.dart` | экономика не вернулась на клиент: контроллер не пишет профиль, статистика пресетов меняется только серверными функциями, а список файлов с прямыми записями не разрастается |
| `test/sql_safety_test.dart` | актуальные определения серверных функций (самые поздние по номеру миграции) не сравнивают `uuid` с `text` без явного каста. Такое сравнение PostgreSQL не приводит неявно — ошибка 42883, которой один раз уже была сломана сдача квестов. Промежуточные версии функций в старых миграциях намеренно не проверяются — это история |
| `test/balance_test.dart` | плавность кривой и правило «энергию нельзя покупать с прибылью» |
| `test/sql_structure_test.dart` | INSERT-блоки в миграциях разбираются, plpgsql-функции закрываются корректно |
| `test/ui_text_test.dart` | стиль текстов интерфейса (см. ниже) |
| `test/widgets_test.dart` | виджеты магазина, промокода и офлайн-логика контроллера |
| `test/path_connector_test.dart`, `test/backend_warmer_test.dart` | отрисовка пути между шагами и прогрев внешнего сервиса |

## Тексты интерфейса

Тексты правятся по единым правилам, и эти правила проверяет `test/ui_text_test.dart`:

- короткая фраза вместо объяснения: «Слот открыт», а не «Вы можете расширить границы своей цивилизации»;
- без восклицаний в системных сообщениях;
- **серия**, а не «стрик»; **эпоха**, а не «эра»;
- заголовки с маленькой буквы — в русском языке нет Title Case;
- ошибка говорит, что случилось, а не «Попробуйте позже» в шести вариантах;
- описание бонуса — это строка статов: «+10% золота за квесты», а не фраза;
- интерфейс не объясняет свою реализацию: вместо «данные сохранены локально» (их никто не сохраняет — локального хранилища в приложении нет) написан честный статус.

Имена собственные — исключение: «Гладиатор Колизея», «Совет Атлетов», названия построек и эпох — это контент, для них Title Case правильный.

## Производительность

Что сделано и почему:

- **Вкладки создаются лениво.** `IndexedStack` строит всех детей сразу, поэтому вкладка «Рейтинг» грузила данные из сети при каждом запуске игры, даже если её не открывать. Теперь вкладка появляется при первом заходе и остаётся в дереве (состояние прокрутки и фильтров сохраняется).
- **Рейтинг строится порциями.** Было `List.generate(currentList.length, …)` — все пятьдесят карточек на каждое обновление состояния. Теперь рисуется страница по 15 строк, следующая подгружается при прокрутке.
- **Рейтинг обновляется при входе на вкладку,** а не при любом изменении профиля. Прежнее условие в `didUpdateWidget` сравнивало поля одной и той же карты (контроллер мутирует её на месте) и срабатывало непредсказуемо. Плюс TTL 20 секунд, чтобы быстрые переключения не дёргали сеть.
- **Убран дублирующий запрос** при переходе на «Рейтинг»: `onTap` тянул `loadGameData` (3 запроса), а вкладка грузила свои (ещё 2–3).
- **Уведомления объединяются.** Одна сдача квеста давала четыре перерисовки всего экрана (старт, обновление списка квестов, успех, сброс флага); теперь одна — через микрозадачу.
- **Шрифт вложен в приложение.** `google_fonts` удалён: он скачивал Nunito с fonts.gstatic.com при запуске, первый кадр шёл системным шрифтом, потом происходила подмена. Теперь `assets/fonts/Nunito-{Regular,Bold,Black}.ttf` объявлены в `pubspec.yaml`, а тема использует `fontFamily: 'Nunito'`. Наличие файлов и отсутствие зависимости проверяет `test/client_invariants_test.dart`.

## Известные ограничения

- **Экономика на сервере.** Награды за квесты, магазин, постройки, эволюция, спасение серии, суточный пересчёт, слоты целей и статистика пресетов — всё считают SQL-функции. Прямыми `update` с клиента остались только смена ника, выбор аватара и правка названия своего квеста — косметика и контент владельца. Список зафиксирован тестом `test/client_invariants_test.dart`, чтобы он не разрастался незаметно.
- **Сдача квеста сравнивает идентификаторы как `text`** (миграция 009). Это безвредный остаток попыток поймать ошибку 42883, которая к падению сдачи отношения не имела — настоящей причиной был тип `last_active_date` (исправлено в 010). Приведение через `::text` не использует индекс первичного ключа, но на квестах одного игрока это единицы строк; когда будет желание — вернуть сравнение по `uuid`.
- **Рейтинг пресетов** пересчитывается сервером из `preset_votes` (`recompute_preset_score`), а политики UPDATE на `goal_presets` для клиента удалены — выставить рейтинг прямым запросом больше нельзя (миграция 015).
- **Таймер фокуса проверяется сервером.** Квест с таймером сдаётся только через серверную сессию (`start_focus_session`), которая фиксирует время старта: сдать раньше нельзя даже прямым вызовом RPC. Не закрывает случай «сидеть и ничего не делать» — это то же поведение, что у добросовестного клиента, и измерение внимания вне задачи.
- **Realtime не используется** — данные подтягиваются pull-запросами, поэтому переключение вкладок вызывает перезагрузку.
- **Правило авторизации на сервере.** Каждая функция, которая принимает id игрока параметром, обязана сверить его с `auth.uid()`. Правило появилось после конечного теста: `complete_quest_atomic` был единственным исключением и позволял сдать квест за другого игрока, зная его id (закрыто в миграции 021). Правило зафиксировано тестом `test/sql_safety_test.dart`.
- **Идентификаторы игроков публичны.** Таблица `profiles` читается по политике `select using(true)` — это нужно таблице лидеров. Значит `id`, ник, эпоха и опыт любого игрока доступны по публичному publishable-ключу. Секретов там нет, но считать эту таблицу приватной нельзя. Id квестов и целей, наоборот, защищены RLS и чужим не видны.
- **Внешний ИИ-backend засыпает.** Генерация целей живёт на бесплатном тарифе Render: контейнер останавливается после ~15 минут без входящих запросов, а пробуждение занимает десятки секунд. Подробности — в [backend-ai.md](backend-ai.md).
- **Backend не входит в репозиторий.** Клиент работает с ним по HTTP-контракту `POST /api/goals/generate`; свой сервис подключается через `BACKEND_API_URL`.
